# The models carved out of the library check into a run of their own.
#
# A handful of models eat most of the check. Measured on a quiet
# machine over 1043 models, the run half cost 3757s in total and three
# of these took 2693s of it - seventy-two percent of the time on three
# names. What they measure is the speed of the numerical solver on a
# large circuit, not how much of the library this compiler reads, and
# they grow dearer on their own as more of them passes. Held in the
# main check they push the library job at its ninety minute ceiling,
# where a cancelled job leaves the same blank space on the page as a
# green one and the commit has been checked by nobody.
#
# So they run on a schedule instead, under `scripts/heavy_floor.sh`,
# which holds its own five floors over exactly this list. Carving a
# model out without giving it a floor would hide its regression for
# ever, which is the one thing this arrangement must not do.
#
# The price and the date it was measured stay beside each name. A cost
# without a date is a cost nobody can check, and this list is the only
# place the decision is written down: what is here is not measured by
# the main check, so anything added here has to be subtracted from the
# main check's floors in the same commit.
#
# The fourth name is carved out of the flatten half rather than the
# run half, and for the same reason. `EngineV6` cost 270.1s to
# flatten against 2032s for all 1040 models - 13.3% of the flatten
# half on one name - and the next dearest model is three times
# cheaper at 83.6s, which is as clean a cut as this list will ever
# get. What it measures is the speed of flattening one large
# mechanical loop, not how much of the library this compiler reads:
# its five siblings in `Loops` read the same classes for a fraction
# of the price.
#
# What does NOT belong here: a model that is dear because it is a
# physical check rather than a speed benchmark.
# `DynamicPipeEnergyConservationCheck` costs 199s and stays in the main
# run, because what it measures is whether the answer is right.
#
# A blank line and a line beginning with `#` are ignored; everything
# else is one class name.
#
# The ten names carved out before 2026-10-06 carried one half of their
# price each. Both halves were measured for them on 2026-10-12, one
# binary built from 86ab6da on an otherwise quiet desk, the ten under
# `--only-from` with `--slow 10` (/tmp/m408/prices.txt): 679s
# flattening and 3967s running between them. Together with the
# thirteen priced on 2026-10-06 and 2026-10-12, every name below has
# both halves and a date, so the split of this list into two jobs, when
# it comes, is arithmetic and not a guess. A run price of 0.0s means
# the model is refused before its first step.
