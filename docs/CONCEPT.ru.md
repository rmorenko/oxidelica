# Oxidelica — концепция

**Современная кроссплатформенная среда физического моделирования на Rust, совместимая с языком Modelica.**

## Зачем

OpenModelica — мощный, но тяжёлый в эксплуатации инструмент: нативной сборки под macOS нет, GUI требует X11/Docker-акробатики, интерфейс архаичен. Oxidelica — попытка построить среду моделирования новой генерации: один нативный бинарник на Mac/Linux/Windows, современный интерфейс и 3D-визуализация на Bevy, ядро на Rust без сборки C-кода на машине пользователя.

## Что это

- **Компилятор языка Modelica** (цель — полная спецификация; путь — поэтапно расширяемое подмножество): парсер → инстанцирование и flattening → символьный анализ ДАУ (сортировка, приведение индекса, tearing) → исполняемая форма.
- **Численное ядро**: явные и неявные решатели ОДУ/ДАУ (RK, BDF/IDA-класс), события, гибридные системы.
- **Среда**: редактор схем, графики, 3D-анимация MultiBody-моделей — всё на Bevy (ECS + wgpu), UI-панели на egui.

## Принципы

1. **Настоящий язык.** Никакого «диалекта»: любой этап парсит подмножество честной Modelica, файлы совместимы с OpenModelica.
2. **Сверка с эталоном.** Каждая модель из тестового набора сверяется с чем-то, независимым от породившего её кода: с замкнутой формой, где она есть (аналитическая траектория, стационар, сохраняющаяся величина), либо со второй формулировкой той же физики.
3. **Каждый этап полезен.** Не «большой взрыв через три года», а инструмент, которым можно пользоваться после каждой вехи.
4. **Один бинарник.** Симуляция интерпретацией/JIT, без вызова системного компилятора C.

**Трек IDE идёт параллельно языковому с самого начала** (решение от 2026-08-15): v0 — Bevy-окно с редактором кода, кнопкой запуска и графиками (готово вместе с M0); далее постепенно — фоновая симуляция, подсветка синтаксиса, схемный редактор (M7) и 3D-сцена (M8) в том же приложении. Языковой трек при этом движется своим темпом: M1, M2, M3…

## Технологический стек

- **Ядро**: Rust, workspace из крейтов: `parser` → `flatten` → `dae` → `sim` → `runtime`.
- **GUI/3D**: Bevy + bevy_egui (панели), wgpu-рендер. Плюс WASM-сборка ядра для веба (позже).
- **Тесты**: cargo test, каждый пример сверен с замкнутой формой или эквивалентной моделью.

## Главные риски

1. **Приведение индекса ДАУ (M3)** — сделано: Pantelides с dummy derivatives, tearing и неявный BDF-решатель. Выбор состояний статический (по численному пивоту в начальной точке); модели, которым нужна смена выбора по ходу счёта — маятник, проворачивающийся на полный оборот, — известный предел реализации.
2. **Длинный хвост семантики MSL (M6)** — закрыт в объёме пакетов вехи. С инструментом поставляется стандартная библиотека в раскладке MSL, и работает та структура, на которой держатся настоящие MSL-файлы: `replaceable`/`redeclare` с проверкой по `constrainedby`, экземпляры `inner`/`outer`, перечисления, условные компоненты вместе с удалением соединений к ним, `if`-уравнения по структурному параметру, уравнения объявления, вложенные модификаторы вплоть до атрибута дочерней переменной, цепочки псевдонимов типов и аннотации, которые MSL пишет на объявлениях, уравнениях и соединениях. Вне объёма пока: переопределение классов (`replaceable package Medium = …`), соединения массивов компонентов и описательные атрибуты (`unit`, `min`, `max`, `nominal`, `stateSelect`) — они разбираются и игнорируются.
3. **Дискретный слой (M9)** — закрыт: переменные, меняющиеся только в событиях, `when`-уравнения с `elsewhen`, `pre`/`edge`/`change`/`initial()`, часы `sample(start, interval)` с точным попаданием шага в момент такта и итерация событий, когда одно событие вызывает цепочку клауз. Секции `algorithm` работают и в моделях: компилятор исполняет их символически в одно уравнение на присвоенную переменную, сливая ветки `if` в выражение и разворачивая `for`. `initial equation` решается методом Ньютона относительно стартового состояния, а объявленные `start` служат начальным приближением. Вне объёма: `while` в алгоритме (компилятор не видит числа итераций) и `when` внутри алгоритма.
4. **Зрелость Bevy как UI-фреймворка (M7)** — редактор схем на ECS нетривиален; митигируем: вся «офисная» часть UI на egui, Bevy отвечает за канву и 3D.

## Спайк (M0) — определение

Срез языка: `model … end`, объявления `Real`/`parameter Real` с атрибутом `start`, секция `equation`, `der()`, арифметика, элементарные функции, `time`, `annotation(experiment(StopTime=…))`. Решатель RK4 с фиксированным шагом, вывод CSV. Критерий: распад и маятник совпадают с аналитикой; код спайка становится фундаментом M1, а не выбрасывается.
