# Modelica Standard Library

Стандартная библиотека Modelica (MSL) — то, чем меряют Modelica-среду:
2671 файл моделей, которые никто не писал под этот компилятор. Ниже —
как её получить, что она здесь делает и чего не делает.

Английская версия файла: [MSL.md](MSL.md).

## Как получить

```bash
oxidelica library add modelica
```

Команда забирает [библиотеку](https://github.com/modelica/ModelicaStandardLibrary)
на релизе 4.1.0 в `~/.local/share/oxidelica/libraries/Modelica` — один из
каталогов, куда поиск и так смотрит, так что модель может сразу называть
`Modelica.Blocks.Sources.Sine`, ничего больше не настраивая. Переменная
`XDG_DATA_HOME` переносит этот каталог, если задана.

Скачивание — это `git clone --depth 1 --branch v4.1.0`, запущенный как
команда, а не HTTP-разговор отсюда: библиотека и есть git-репозиторий,
git сам сверяет скачанное с запрошенным тегом, а компилятор остаётся без
собственного сетевого стека.

Другие библиотеки берутся так же, по URL:

```bash
oxidelica library add https://github.com/example/Library.git --version v2.0 --as Example
```

`oxidelica library list` показывает, какие библиотеки в поле зрения и
сколько файлов в каждой. Библиотеку, уже лежащую на диске, скачивать не
надо: её называет `MODELICAPATH` — одну или несколько.

## Что получается

`oxidelica library check <каталог>` читает каждый файл библиотеки и
каждую модель-пример в ней и говорит, докуда дошёл. На момент написания,
против MSL 4.1.0:

```text
files: 2671 read, 0 not read
classes: 7631; example models: 1043, of which 472 flatten and 131 run
runnable examples (experiment or Example icon): 912, of which 383 flatten and 128 run
```

Четыре числа, и они про разное. **Read** — это парсер: файл понят как
Modelica. **Flatten** — фронтенд: модель инстанцирована, соединения
разрешены, массивы и функции развёрнуты, на выходе плоская система
уравнений. **Run** — всё остальное: эта система оказалась разрешимой и
прошла десять шагов без жалоб.

**Runnable** — последняя строка, и это честный знаменатель. Проверка
зовёт примером всё, у чего в имени есть `.Examples.` или `.Test`, а
библиотека держит части примеров там же, где сами примеры: схемы на
операционном усилителе с выводами, которые никто не питает, регуляторы,
чью постоянную времени задаёт объемлющая модель. Часть сама по себе не
модель чего-либо и запуститься не может, так что считать её провалом
компилятора — сказать неправду дважды: спрятать выигранное и направить
работу туда, где система и не должна была замкнуться. Настоящий пример
отмечен тем, что читает инструмент: аннотацией `experiment` со временем
остановки или иконой `Icons.Example`, унаследованной через шаблон или
напрямую.

Чтение идёт на семи ядрах из десяти, чтобы машина оставалась пригодной
для работы, пока проверка идёт; `OXIDELICA_THREADS` говорит иначе, если
машина нужна целиком.

Разрыв между двумя последними — ради него их и считают порознь. Долгое
время мерилось только среднее число, и оно льстило компилятору: плоская
система, которую никто не решает, — не ответ, а две ошибки, найденные,
пока это писалось (класс, унаследованный по двум путям ромба и
удвоивший каждую переменную; массив записей, получивший значение не тем
боком), месяцами давали неверные плоские модели без единого отказа.
Уплощение говорит, что у фронтенда возражений не было. Прогон — что
возражение стоило бы иметь.

Десять шагов, а не полная симуляция, и не дальше, чем модель сама
останавливается. Что ломается на этой стадии, ломается в начале —
несбалансированная система, параметр, который никто не задал, имя,
которое ничего не значит, — а полный прогон сказал бы немногим больше
ценой минут на модель.

Оба числа двигаются по мере того, как файлы начинают разбираться, и не
всегда вверх. В файле, который никто не смог прочитать, лежат классы,
которых никто не может назвать, а вызов имени, которого ничто не
определяет, оставляют стоять, а не отвергают, — и модель, дотянувшаяся
в непрочитанный файл, могла уплощаться, молча неся вызов в никуда.
Когда файл начинает разбираться, вызов находит своё объявление, в
объявлении написано `external "C"`, и модель отвергается по имени. Это
не шаг назад, а приход честного числа: так сдвинулось 26 моделей, когда
`Modelica/Blocks/Tables.mo` начал разбираться.

Разобранный пример — RC-цепочка целиком из компонентов MSL:

```modelica
model MslRc "An RC circuit built from Modelica.Electrical.Analog"
  Modelica.Electrical.Analog.Basic.Resistor r(R = 100);
  Modelica.Electrical.Analog.Basic.Capacitor c(C = 1e-4, v(start = 0, fixed = true));
  Modelica.Electrical.Analog.Sources.ConstantVoltage source(V = 5);
  Modelica.Electrical.Analog.Basic.Ground ground;
equation
  connect(source.p, r.p);
  connect(r.n, c.p);
  connect(c.n, source.n);
  connect(source.n, ground.p);
  annotation(experiment(StopTime = 0.05, Interval = 0.001, Tolerance = 1e-10));
end MslRc;
```

`RC = 100 × 1e-4 = 0,01 с`, значит при `t = 0,05` замкнутая форма даёт
`5(1 − e⁻⁵) = 4,9663103`. Расчёт отвечает `4,966310`.

Ещё один — там, где блок спрашивает ответ у C, а этот компилятор ответ
выписывает:

```modelica
model TableRamp "A table of the standard library, read where the model wrote it"
  Modelica.Blocks.Sources.CombiTimeTable t(table = [0, 0; 1, 2; 2, 6]);
  Real y;
equation
  y = t.y[1];
  annotation(experiment(StopTime = 1.5, Interval = 0.5, Tolerance = 1e-10));
end TableRamp;
```

`[0, 0; 1, 2; 2, 6]` — это две прямые, наклон два до `t = 1` и наклон
четыре после, значит при `t = 1,5` замкнутая форма даёт `2 + 0,5 × 4 = 4`.
Расчёт отвечает `4,000000` и ставит событие на изломе.
`Modelica.Blocks.Tables.CombiTable1Ds` читается так же, только абсцисса
у него `t.u`. Что стоит за обоими — в [EXTERNAL.ru.md](EXTERNAL.ru.md).

Этим нужна библиотека, а моделям в `examples/` — нет; поэтому они лежат
здесь.

## Чего не получается

25 файлов, которые не разбираются, и модели, которые не уплощаются, —
это не длинный хвост мелочей. Это несколько возможностей, каждая из
которых используется широко:

- **Тела на C** — прежде всего таблицы по времени, затем генераторы
  случайных чисел, привязки к LAPACK, чтение файлов. Строки и
  одномерные таблицы уже отвечаются здесь; остальное разбирается и
  отвергается в месте вызова, называя, чего именно просили. Как это
  должно измениться — в [EXTERNAL.ru.md](EXTERNAL.ru.md).
- **Локальная, присвоенная в одной ветке** — 41 модель, среди них
  свойства воды из библиотеки сред.
- **Значение в объявлении записи** — `Complex v[m] = ...` не говорит
  модели ничего, тогда как уравнение той же формы говорит.
- **Библиотека многотельной механики** — на цепочке длин и форм,
  которыми нарисованы её видимые части.

Две группы моделей, 73 вместе, отвергаются ни по одной из этих причин:
их просто не удаётся досчитать. Что про это измерено и что два измерения
сказали неверно — в [EXPANSION.ru.md](EXPANSION.ru.md).

Список измерен, а не угадан: `library check` ранжирует причины по тому,
как часто каждая встретилась, и работа идёт по этому ранжированию.
`library check --list` называет уплощаемые модели — это и отличает шаг
вперёд от шага вбок.

## Совместимость как правило

Библиотека — это груда, из которой модель берёт угол. Файл, который не
разобрался, откладывается в сторону, а не делается проблемой всех: модель
рядом всё равно загрузится, а та, которой нужно было что-то из
непрочитанного файла, упадёт дальше и по имени. Именно это делает
осмысленным число вроде «419 из 767»: без такого правила один неразобранный
файл сделал бы всю библиотеку негодной, и число было бы нулём.
